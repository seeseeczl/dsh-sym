# CR-0007 技术方案｜提交记录 + 重置 / 回滚

## 结论先行

1. **视图正文没有 `sessionId`，只能从 DOM 祖先读。** `conversation.view` 渲染时传的是
   `{ inspectCall, viewRequest, openView, completeViewRequest }`（asar
   `dsh-client-ui-conversation/lib/client.js` 里 `renderSlot("conversation.view", {…})`
   就这一份），**没有 sessionId**。而外层 `[data-conversation-content]` 由官方硬编码带
   `data-conversation-session="<id>"`，所以 `sessionIdOf(node)` 沿 `parentElement` 向上找。
   按祖先收窄（而不是 `document.querySelector` 取第一份）是**多实例安全**的唯一写法：
   右侧栏聊天标签、子代理面板各有一份会话。
2. **`git log` 的记录分隔是 `%x00` + 换行。** 真机踩到的坑：`%x00` 之后 git 会另起一行，
   所以 `stdout.split('\0')` 得到的每条都带一个前导 `\n`；不剥掉它，`%H` 的格式校验会把
   **每一个提交**都判成坏行 —— 界面表现是"列表永远为空"，而且不报错。
   守卫见 `test/host.test.mjs` 的「真实 git 的分隔是「<NUL><换行>」」。
3. **冲突后留下的是 `REVERT_HEAD`，不是 `CHERRY_PICK_HEAD`。** 第一版只查后者，导致
   "已有未完成的回滚"这层保护完全失效：之后每次 `revert` 都被 git 以
   "you have unmerged files" 拒绝，而界面上没有任何中止入口。现已两个 ref 都查，
   并把状态随列表一起下发（刷新页面后仍能提示），另提供 `revert-abort`。
4. **`reset` 不给 `--hard`。** 三个 mode 的语义与保留范围如下；`--hard` 会静默丢弃
   未提交改动，属"不替用户做的决定"，因此不在枚举里，且在到达 git 之前就被拒。

| mode | HEAD | 暂存区 | 工作区 | 未提交改动 |
| --- | --- | --- | --- | --- |
| `soft` | 移动 | 保留 | 保留 | 全部保留（已暂存） |
| `mixed` | 移动 | 重置 | 保留 | 全部保留（未暂存） |
| `keep` | 移动 | 重置 | 重置 | 无冲突则保留 |

## 宿主

### 读取（`log`）

```
git log --no-color --max-count=<n+1> --skip=<offset> \
        --format=%H%x09%h%x09%an%x09%at%x09%s%x00 HEAD --
```

- 格式串**由宿主写死**，调用方给不了格式指令；主题排在**最后一列**，因为它是唯一的
  自由文本，含制表符时也不会挤掉前面的列。
- 多读一条（`n+1`）判断 `hasMore`，省掉第二条 git 命令。
- `limit` 夹在 `[1, 200]`，`skip` 负数按 0。
- 不缓存：历史只在提交时变，一页旧数据比多起一个进程更糟。
- 空仓库（`git init` 后无提交）返回空列表而不是 null —— "没有提交"是有效答案。

### 写入（`reset` / `revert` / `revert-abort`）

- 统一先把 id 解析成完整哈希：`git rev-parse --verify --quiet <id>^{commit}`。
  解析不到 → `unknown`；语法不像 id → 连 `rev-parse` 都不跑。
- 写命令各用 `AbortSignal.timeout(GIT_WRITE_TIMEOUT_MS = 30s)`，**不复用请求 signal**。
- `reset --<mode> <hash> --`：mode 是封闭枚举，其他值 → `invalid`。
- `revert --no-edit <hash> --`：`--no-edit` 是必须的（无终端，不能让 git 开编辑器）。
  执行前先查 `revertState`，有在途 → `busy`。
- `revert --abort`：收拾冲突留下的半个回滚。没有在途 → `idle`。
- 冲突判定：stderr 含 `CONFLICT` / `Automatic merge failed`，或解析出挡路文件 →
  `code: 'conflict'`，附带 `files` 与 `revert` 状态。

### 路由映射

| 请求 | 成功 | 失败 |
| --- | --- | --- |
| `GET ?kind=log` | 200 一页 | 400 缺 sessionId / 404 非仓库 |
| `POST { action:'reset' }` | 200 + 新读数 | 400 未知提交或非法 mode / 409 git 拒绝 / 503 无 git |
| `POST { action:'revert' }` | 200 + 新提交短号 | 409 冲突或拒绝 / 400 未知提交 |
| `POST { action:'revert-abort' }` | 200 + 新读数 | 400 没有在途（`idle`） |
| `POST { branch }`（无 `action`） | 200 | 同 CR-0002 **不变** |

`action` 缺失即老的切分支路径 —— CR-0002 的回归靠这一点守住。

## 客户端

- 表格是 CSS grid 五列（描述 / 提交 / 作者 / 日期 / 占位），容器查询在窄窗口依次
  收起作者、日期，**不影响官方头部布局**（正文在 `conversation.view` 槽内，自带滚动区）。
- 状态机：`no-session` / `loading` / `unavailable`(404) / `failed` / `ready`。
  404 不当故障（"不是仓库"是正常态，安静说明）；其余失败给「重试」。
- 已读页缓存在模块级 `Map<sessionId, page>`：切走再回来先画旧数据，同时后台重取，
  不闪空白也不显示过期数据。
- `reqSeq` 丢弃过期响应：连点「加载更多」时后到的旧页不能盖掉新页。
- 写操作前**二次确认**（提交号 + 标题 + "不会推送"），写成功后重取第一页。
- 有未完成的回滚时，顶部条与菜单都给出「中止这次回滚」。

## 后续修订（用户实机反馈后）

用户看到真机效果后提了两轮修正，都是可用性问题，不是换设计：

1. **作者列去掉、宽度压缩**：五列改四列，描述列多出约 200px。作者对"挑一笔提交"这个动作不是
   决策字段（它不参与识别，也不参与排序），去掉后每行更能读。
2. **行头分层 + 日期右对齐**：状态行（分支·仓库·条数）与列标题原来只隔 8px，读起来像两行并列的
   标题。改成隔 12px 分成两组；日期是绝对时间，按 `V3.1` 归数字列，右对齐 + 等宽数字，
   表头与内容同对齐。间距也全部收回 `V4.1` 的刻度表（上一轮给的 20px / 28px 不在表内）。
3. **左侧让开快捷竖条**：竖条是 `position: fixed` 的全局覆盖层，`left = 侧栏右缘 + 8`，宽约 38px；
   而表格容器左缘也在侧栏右缘，所以这段偏移是**固定**的 —— `padding-left: 48px` 能稳定避开，
   不需要量像素、不需要重试（与 AGENTS.md 否掉的"fixed 借位"不是同一类做法）。
4. **提交时间同年省略年份**：`2026-10-16 12:43`（19 字符）在 104px 列里偏挤，
   改用 `10-16 12:43`（11 字符）；跨年才显示 `2025-12-03` —— 省掉年份会把两年混成一列。
   完整时间放进 `title`，悬停可核对。列宽 148 → 104，省下的宽度归描述列。
5. **`--hard` 的损失可量化**：`log` 载荷加 `dirty`（`parseGitStatus().files`，已跟踪文件的
   未提交改动数）。确认框据此分三档：干净 → "不会有未提交改动丢失"；有改动 → "具体来说，
   N 个已跟踪文件的未提交改动会被丢弃"；老宿主没给字段（null）→ 不声称任何数字。
   **只数已跟踪文件**：`git reset --hard` 不删未跟踪文件，把它们算进去是误导。
   ⚠ 实现时踩了一次：`parseGitStatus().files` **本身就是计数**（数字），写成 `.files.length`
   会恒得 `undefined` —— 靠新加的宿主测试抓出来。
6. **三个动作改用图标，并首次提供 `--hard`**：文字按钮（「重置到此提交」「回滚此次提交」）
   在两个 104px 里放不下，溢出后压住日期列 —— 真机截图里能看到文字叠在一起。
   改为三个 20px 图标（68px 总宽），靠形状与颜色区分：
   * 圆弧箭头 = 重置到此处（`reset --mixed`，改动全留）
   * 双左箭头（危险色）= 回滚到此处（`reset --hard`，丢弃后续提交与未提交改动）
   * 撤销箭头 = 回滚此次提交（`revert`，生成反向提交）

   **`--hard` 是本 CR 的立场改变**：早先写的"永不 --hard"被用户明确需求推翻
   （"回滚 = 丢失后面的修改，恢复到某个备份点"）。保留的安全措施：它是唯一带危险色的按钮、
   确认框逐项写明会丢什么、且仍然只走 argv（`reset --hard <完整哈希> --`）不碰远程。
6. **重置 / 回滚改成行内按钮**：用户明确要求"要有按钮"。原设计是「选中一行 → 打开菜单」两步，
   在真机上等于功能藏起来了。改为每行右侧两个按钮（网格最后一列 104px），点哪行对哪行：
   回滚直接进确认框；重置先弹模式菜单（软/混合/保留）再确认。「中止回滚」也从菜单里搬到
   表格下方提示行。行不再是可点选中的按钮 —— 没有"选中态"这个概念了。
5. **去掉顶部状态条**：`分支 · 仓库名 · 条数` 三个字段在别处都有或不必常在，整条移除。
   按钮移到表头最右（网格最后一列 88px），仍在 sticky 表头里，滚动时可见；
   「未完成回滚」的提示改到表格下方，只在真有半个回滚时出现。
6. **宽度跟对话内容区一致**：取官方 `--dsh-chat-content-width`（定义在 `.kiGsTW_body`，
   正是本视图的祖先；值 680–920px，用户拖输入框时由 `--dsh-chat-user-width` 覆盖），
   用 `max-width: calc(var(--dsh-chat-content-width, 100%) + 96px)` + `margin-inline: auto`。
   内距左右各 48：左边那 48 同时是避开快捷竖条的固定补偿；左右相等才能让**内容左缘与对话
   内容左缘重合**（实测容器 1100/1400/1800 时完全对齐）。变量缺失时 `calc(100% + 96px)`
   大于容器 → 不限制，不会塌成 96px。
7. **列宽改为固定，取消拖拽**（用户决定，2026-11-03）：可拖手柄三根 + 列宽持久化整体撤除，
   改用 `1fr / min-content / min-content / 80` + 统一 16px 列间距。
   **提交与时间用 `min-content` 而不是固定 px**：固定 92px 承载 50px 的哈希，列内空出 42px，
   再加 16px 间距，视觉间隔 58px 显得散。自适应后列内无空白，间隔就是 16px。
   代价是这两列不能再有 `text-overflow:ellipsis`（会退化成被压扁的宽度），已改为纯 `nowrap`。
   窄屏收起时间列后剩三列。客户端因此少了约 60 行，余量回到 149。
8. **三个按钮分色**：重置（`reset --mixed`）= warn 黄；两个回滚（`reset --hard` / `revert`）= error 红。
   黄红两色直接对应"不丢东西 / 会丢东西"，比统一灰色更快分辨。形状仍用来区分两个红色动作。
9. **列宽可拖拽**：两根 12px 的手柄列插在网格里（取代原来的 `column-gap`），拖左边界即改该列宽，
   松手写本机存储。用网格列而不是绝对定位手柄，是因为绝对定位需要知道每列像素位置，
   而描述列是 `1fr`，位置无法从 CSS 推定。窄屏收起日期列时，它左边那根手柄用同一个
   `dshLog_colDate` 类一起收起，网格同步降到 4 列。

## LOC 阈值调整的理由

| 模块 | 改前上限 | 实测 | 改后上限 |
| --- | --- | --- | --- |
| M-HOST | 1800 | 2016 | 2100 |
| M-CLIENT | 3800 | 4036 | 4100 |
| M-CLIENT（后续修订） | 4100 | 4100 | **4150** |

最后一档的理由：列宽可拖拽实到 4100，正好贴死上限、**余量为 0**；零余量会让下一次任何小改
都只能在压力下草率压缩，故留 50 行。

本 CR 净增的是**一个完整视图**（列表 + 分页 + 两个写操作 + 中止 + 确认框 + 状态机）
与**三种新的 git 动作**（含冲突处理）。按历史惯例（CR-0001/0002/0003/0005 各调一次），
阈值调到"实测值 + 少量余量"；客户端半边仍不能拆文件（`file://` 挂载没有 bundle URL，
`require.async` 解析不到 chunk），后续增长仍需优先就地压缩。
